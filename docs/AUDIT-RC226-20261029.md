## A3 — Parser engine: contratto verificato e correzione

File: `js/roi-engine.js`; regressioni `tests/roi-missing-inputs.test.js`.

Prima: `expenses:null` era costo0; `equity:null` era capitale0; `interestRate:null` era tasso0. `Number(null)` superava il controllo di finitezza. Non era stato dimostrato un passaggio di null dalla normale form.

Esaminati tutti i chiamanti di produzione: app.js/Analizza, preview inline home, bb-demo-model.js, financial-review.js e i sette punti di ricalcolo del chatbot-orchestrator. Analizza passa valori numerici dopo la validazione della form; demo valida gli input; financial-review rifiuta snapshot incompleti prima dell'engine; home e chatbot costruiscono valori numerici con default dichiarati. La home usa durata0 senza debito: questo caso resta valido.

Contratto mantenuto/definito:

| Input | Comportamento |
|---|---|
| Campo omesso o undefined | Default opzionale esistente, invariato |
| null, stringa vuota/spazi, booleano, array/oggetto numerico | RangeError con code `roi/invalid_input`, nessun risultato finanziario |
| NaN/Infinity o stringa non numerica | Stesso errore esplicito |
| Zero numerico o stringa numerica "0" | Zero intenzionale conservato; restano le regole preesistenti sulla durata con debito |
| Oggetto input null/non valido | Errore esplicito |

Default invariati: prezzo100000 (owned0), equity0, debito inferito secondo modalità, notte100, occupazione65, costi0, commissioni15, imposte21, TAN3,5, durata20. I default sono ipotesi dell'engine per chiamanti che omettono campi, non evidenza con cui riempire report storici. Un chiamante che ha già convertito un valore in0 non consente all'engine di ricostruirne l'origine: questa patch non interpreta retroattivamente i numeri salvati.
